> 2026-10-15 改版。车主："the client is still not suitable for a user, too complex

> 刷固件变成**看得见的三步**，术语换成人话（技术值收进「高级」）。
> 2026-10-16 打包 + 客户端集成。车主："把（已经验收的）车主模式编辑器打进 PC 客户端。"

> 编辑器的那几个静态文件真正**打进 exe**（离了仓库也能改色、换图、导出 `assets.bin`），
> 而且**在客户端里**保存安装包之后可以直接选串口写进板子。

## 怎么启动

双击 `tools\app\run.bat`（或者命令行 `python tools/app/server.py`），它会：
1. 起一个**只监听 127.0.0.1** 的本地服务（默认 <http://127.0.0.1:8787>）；
2. 自动打开应用页。

想要"像原生窗口"（无地址栏）：`run.bat --app-window`。
换端口 / 不自动开浏览器：`run.bat --port 8899 --no-open`。

## 打包成可执行文件（一个 exe，双击即用）

```powershell
powershell -ExecutionPolicy Bypass -File tools\app\build-exe.ps1 -OneFile
# → tools\app\dist\206Dash-Workbench.exe   （约 10MB 上下，单文件，不需要装 Python）
```

用法（双击也行，双击时自动找仓库、自动开浏览器）：

```
206Dash-Workbench.exe                       # 自动找仓库 + 打开浏览器
206Dash-Workbench.exe --app-window          # 无地址栏窗口（更像原生应用）
206Dash-Workbench.exe --repo <仓库路径>      # 明确指定仓库（找不到仓库时用）
206Dash-Workbench.exe --port 8899 --no-open
```

设计上的三条（都实测过，见 §"验过什么"）：

1. **界面文件与编辑器都内嵌在 exe 里**（`--add-data`）⇒ **没有仓库也能打开界面、
   也能改配色 / 换图片 / 框选 / 导出 `assets.bin`**；
   仓库只在"构建固件 / 跑预览"这些真需要它的地方才用到，找不到时**明说缺哪个路径**
   （不静默失败）。
   编辑器那几个静态文件是**抓请求日志**定的清单，不是猜的 —— 见 `server.py` 的
   `ALLOWED_EDITOR_FILES` 与 `build-exe.ps1` 的 `--add-data`（一一对应，含
   `image-editor.html` 那个老链接的重定向薄壳）。
   服务时**仓库里那一份优先**，仓库不在才用包内那份。
2. **exe 自己找仓库**：`--repo` > 环境变量 `DSH_206DASH_REPO` > 从 exe 位置往上找
   （标志是同时存在 `platformio.ini` 与 `tools/app`）> 从当前目录往上找 > 本机默认路径。
   找不到会在界面上明说**缺哪个路径**（`/api/health` 的 `repo_need`），不装作正常。
3. **用 `--console` 而不是 `--noconsole`**：日志本身就是这个工具的一部分；
   退出走界面右下角的**「退出应用」**按钮（`POST /api/quit`），不需要去找那个黑窗口。

★ 需要 `pip install pyinstaller`（这台机器上装在项目 venv 里，版本 6.22.3）。
★ `tools/app/dist/206Dash-Workbench.exe` **是仓库里的一份文件**（`.gitignore` 只忽略
  `tools/app/build/` 与 `*.spec`）—— 重打之后按正常流程提交即可。
★ Windows SmartScreen 可能对"没有签名的新 exe"弹一次警告 —— 选"仍要运行"即可。

## 三个屏，能力一项没少

车主只干四件事：① 刷固件 ② 改颜色 ③ 换图片 ④ 看效果。所以顶栏就是三个屏：

| 屏 | 收进来的东西 | 一句话 |
|---|---|---|
| ① **刷固件** | 原「无线刷写」+「开发板状态」 | 三步：选哪块表（**转速表（左）/ 速度表（右）**两张卡片）→ 固件（自动挑最新的那个）→ 一个「开始升级」按钮（上传 + 重启 + 确认成功都在它后面） |
| ② **表盘** | 原「主题配色」+「图片素材」+「预览表盘」 | 编辑器**只有一个框**（`tools/theme-editor/index.html`）：「主题配色 / 图片素材」两颗页签指的都是它，只是让它切到那个页面里的**页内分区**（图片 = `#images` 锚点，老「图片页」的地址就是这个锚点）；预览仍是 `initPreviewInline()` 那套注入 |
| ③ **工具** | 原「文件与烧写」+「总览」里的零碎 | **把表盘写进板子**（用编辑器当前状态，**不存文件**；下拉带角色、可一次写两块板、单块照旧）、刷一份已经存下来的文件（折叠区）、读固件文件；「构建新固件」收进「高级」（车主不需要知道 env 是什么） |

技术值一个没删，只是都收进「高级」折叠区：固件来源（本机选文件）、板子地址、板子串口、
板子返回的原始 `/status`（含 `heap_kb` 这类字段）、原始固件列表、原始日志、构建档位（env）。
车主看不懂的词（OTA / 热点 / 槽位 / running / target / env / bin / slave / master）
**只允许出现在「高级」里** —— 这一条由静态闸门看着（见下）。

### 在客户端里刷，**不用先保存**（2026-10-15，车主反馈）

车主原话："为什么每次刷写都要保存一次 bin 呢，这样我的下载文件夹会有很多个相同的 bin。"
⇒ **两件事分开**：

| 想干什么 | 点什么 | 会产生文件吗 |
|---|---|---|
| **刷进板子**（用编辑器里**当前**的颜色/图片） | 「工具」屏的「写进这块板（配色+图片，不存文件）」/「写进两块板（…不存文件）」 | **不会**（在内存里打好容器就直接发给本地服务） |
| **留一份快照**（万一以后想刷回这一版） | 「表盘」屏 → 编辑器里的「保存安装包」 | 会（存到下载文件夹，一次一份） |

- 「写进这块板 / 写进两块板」的做法：现场问「表盘」屏那个编辑器框要**当前状态**的容器
  —— 走它**唯一**那条打包路（`exportAssetsBin()` → `ImageBlob.build` + `AssetPackageCore.packBytes`），
  外壳只是把它的 `download()` **临时截下来**（拿到字节就还原）⇒ `<a download>` 那一下
  根本不会发生，下载文件夹里不会多东西。**外壳自己不打包**（没有第二套内核）。
- 构建不出来就**明说为什么**（把编辑器状态栏那一句原样带出来，例如"构建失败：还没有图片…"），
  不静默、也不会硬编一份空容器去刷。
- 想刷**已经存下来的**文件（比如上次的快照）：卡片里「想刷一份已经存下来的文件」那个折叠区
  —— 那是原来那条路，**没删**。
- 编辑器页面**在客户端之外**打开时（`file://` 双击，或别的静态服务器）：没有 `/api/flash`，
  那一块「写进板子」照旧**不出现** ⇒ 只能手工用 esptool，所以那种场景下**仍然要先保存一份文件**
  （原来那条 esptool 命令一个字没改）。
- 判据：`check-live-flash.js`（把 app.js 那三个函数抠出来喂一个假编辑器 window ⇒
  **真的 `download()` 一次都没被调到**、失败有明确说法、与编辑器的名字约定还在）；
  加上 `check-flash-offset.py` 里"三条路都没有偏移字段"那几条。

### 串口标出角色 + 一次写两块板（2026-10-15，车主反馈）

车主原话："标出角色吧，分别是新板（未定义），主板，从板，而且你写进板子这个只有一个
按钮，也没区分主/从板啊。" ⇒ 「工具」屏那张写素材的卡片上：

- **端口下拉里带角色**：`COM9（MASTER · 右屏 速度+进气）` / `COM8（SLAVE · 左屏 转速+水温）`；
  认不出来就写 `COMx（角色未知）`；主板板载口那种写 `COMx（不是本项目的板）`。
  （编辑器的串口下拉读的是同一个 `GET /api/ports`，它的 `detail` 就是这一行 —— 所以那边
  **一行代码没改**也跟着带上了角色。）
- **「写进两块板（配色+图片，不存文件）」**：两块板通常同时插着 ⇒ 一次点击**依次**写完，
  **逐块报结果**（哪块成了、哪块没成各一行；有失败就点出来并说明可以单独重刷它，
  绝不把失败说成成功）。单块那颗「写进这块板」**照旧保留**。
- 仍然只调现成的 `POST /api/flash`（`kind=assets`，偏移服务端白名单取 `0x210000`）——
  **没有第二套刷写实现**，请求体里也没有"偏移"这个字段。

**角色是怎么认出来的**（`server.py` 的 `ROLE_CACHE_PATH` 那一段，全是证据，不是猜）：

| 证据 | 拿到什么 | 强度 |
|---|---|---|
| `pio device list` 那一行里的 `SER=` | **板子的 MAC**（乐鑫原生 USB `303A:xxxx` 才是；CH34x 串口桥的 SER 是桥片的，认不出就写"未知"） | MAC **不变**，COM 号会变 ⇒ 认板子靠它 |
| 板子自己起的 AP 名 `206dash-MASTER\|SLAVE` + 电脑此刻连着的 `BSSID` | 角色 ↔ MAC 的**现场**绑定 | 最强（`netsh wlan show interfaces`，只读） |
| 板子自报的 `role=`（`GET /status`，既有能力） | 同一件事的第二份证据 | 要求"连的就是这个角色的板子 AP"才写缓存 |
| 缓存文件 `C:\206dash-scratch\app-board-roles.json` | 上次学到的映射 | 显示时带 **未确认** 标记；删掉文件 = 忘掉重认 |

★ **拿不到证据就是「角色未知」**，绝不按 COM 号 / 插拔顺序推。这条有可执行判据：
`check-port-roles.py`（喂今天真机那份 `pio device list` 文本 + 构造的 netsh 文本，
**不打开任何串口**；其中一条就是"连着家里路由器读 /status 时不许把路由器的 MAC 记成板子的角色"）。

### 「点了没反应」那一课：界面是哪一份、有没有缓存、要不要重启（2026-10-16）

车主实测："点了 写进板子 按钮好像没反应。" 查下来是三件事叠在一起，现在都钉住了：

1. **写入按钮放到了车主正在看的那一屏**：「表盘」屏编辑器框上面就是
   「写进这块板（配色+图片，不存文件）」/「写进两块板（不存文件）」——
   不用先去编辑器里「保存安装包」（那是留快照），也不用跑去「工具」屏。
   点下去**立刻**有反馈：按钮自己变成「正在写 COMx…」、旁边那个小牌子跟着变；
   每种失败都说清为什么（还没放图片 / 没认出串口 / 端口被占用 / 版本不对…），
   **绝不"点了什么都不说"**。
2. **界面只从一处发，不许混搭**：`server.py` 的 `pages_source()` 一处决定
   —— 仓库里 `tools/app` 与 `tools/theme-editor` **都在** ⇒ 整份用**仓库**；
   否则整份用 **exe 包内**。以前是"每个文件各自兜底"，会出现"外壳是新的、编辑器是旧的"
   这类混搭（症状正是"按钮在、点了没反应"）。
   **哪一份**从 `/api/health` 的 `pages_from` / `pages_dir` / `app_js.sha8` /
   `editor_html.sha8` 如实报出来，页面右上角也显示一行：
   `界面：仓库（app.js 1a2b3c4d · 编辑器 5e6f7a8b · 2026-10-16 18:47）`。
3. **版本自检**：外壳在编辑器框载入时（以及每次要写之前）校验它需要的函数
   （`exportAssetsBin` / `download`）**在不在**；缺就当场喊
   「编辑器页面版本过旧：缺 XXX —— 右下角「退出应用」之后重新双击那个 exe
   （或按 Ctrl+F5）」，并且**不发** `/api/flash`（不拿旧页面瞎写）。
4. **所有静态响应一律 `no-cache`**（`Handler.end_headers()` 里统一加一处
   `Cache-Control: no-store, no-cache, must-revalidate`）：本地工具页每次都从磁盘读，
   不再出现"改了代码、重启了客户端，页面上还是旧的、非得 Ctrl+F5"。
5. ★ **换过 exe / 更新过代码之后**：右下角「退出应用」把旧进程关掉，**再重新双击**
   那个 exe —— 让旧进程继续跑，看到的就还是旧的那一份。

判据（**真浏览器真点击**，不是静态字符串）：

```powershell
<真 python> tools\app\check-click-flash.py            # 起 server.py + headless Chrome
<真 python> tools\app\check-click-flash.py --exe tools\app\dist\206Dash-Workbench.exe
```

它点那颗按钮、一路跟到 `/api/flash`，查：点下去 0.25 秒内有没有可见变化、
请求体是不是 `{port, kind:"assets", path}`（**没有偏移字段**）、
没图片时是不是说清了原因、版本旧时是不是当场喊、下载目录里有没有多出 `.bin`。
★ `/api/flash` **在页面里被拦掉**（fetch 换成假的，只记账）⇒ **绝不碰板子**；
服务端日志里也不许出现 `POST /api/flash`（这一条也查）。本机没 Chrome 时它会说一声跳过。

## 为什么是"本地服务 + 网页应用"，而不是 Electron / 安装包

- **零安装**：只用 Python 标准库 + 一个浏览器。Electron/Tauri 要 Node/Rust 工具链
  和几百 MB 依赖，而这个仓库的机器上已经有 Python 与 PlatformIO。
- **同源**（关键）：把仓库根目录挂在一个 `http://127.0.0.1` 源上之后，
  四个页面就是**同源**的 ⇒ 应用外壳可以 iframe 收进来、将来也能跨页取数据；
  `file://` 下每个文件是独立源，这些都做不了。
- **安全上下文**：`http://127.0.0.1` 算安全上下文 —— WebSerial / 直连板子热点都需要它。
- **该在后端的在后端**：列串口、跑 esptool、跑 platformio 一律由 `server.py` 执行，
  而且**只认白名单**（env / 分区偏移 / 操作都写死在文件里）；页面传来的字符串只当"键"用。
- 想再"像应用"一点：`--app-window` 就是无地址栏窗口；将来真要做安装包，
  这一层原样保留、外面套个壳即可。

## 后端做了什么（`server.py`）

| 接口 | 作用 | 边界 |
|---|---|---|
| `GET /tools/app/<4 个文件>` | 应用自己的界面文件 | 只看这 4 个；仓库优先、包内兜底 |
| `GET /tools/theme-editor/<文件>` | 编辑器页面那几个静态文件 | 只看 `ALLOWED_EDITOR_FILES` 那 7 个；**仓库优先、包内兜底**（离了仓库编辑器仍能用） |
| `GET /api/health` | 服务自检（仓库路径 / **缺哪个路径** / pio 解释器 / 代理） | 只读 |
| `GET /api/ports` | 列串口（`pio device list`）**+ 每口的角色**（MAC/SER、是不是本项目的板、主板还是从板、证据来源） | 只读（另加一次只读的 `netsh wlan show interfaces` 看当前 WiFi） |
| `GET /api/bins` | 列各 env 的 `firmware.bin`（大小/时间/是否 `-ota`） | 只读 |
| `GET /api/bin?env=…` | 把某个 env 的固件吐给页面（OTA 上传用） | env 白名单 |
| `POST /api/upload` | 页面选的文件落盘到 `C:\206dash-scratch\app-upload\`（≤16MB） | 只接单文件 |
| `POST /api/flash` | esptool 写素材分区（单块 / 两块都用它，**只有这一个刷写入口**） | 端口必须 `COM\d+`；分区只允许 `theme/assets/image`；**偏移只从白名单取**（页面传不进来）；文件必须在仓库或 scratch 内 |
| `GET /api/board-status` | 读板子自报的 `/status`（既有能力）**+ 顺手把 `role=` 与当前 BSSID 绑起来缓存** | 只读 |
| `POST /api/build` | `platformio run -e <env>` | env 白名单 + **要求仓库在**（不在就明说缺哪个路径） |
| `POST /api/preview` | 跑 40 秒 `pcpreview` 落帧 | 固定 env + **要求仓库在** |

★ 边界就这些：**没有任意 shell、不能越出仓库、不能指定任意偏移**。
  要加能力就照这张表的风格加 —— 新增的每一行都是一次"要不要开放"的决定。

## 静态闸门

```powershell
node tools/app/check-app.js
```

它钉的是"我在这台机器上点不了浏览器"时最容易漏的几件事：
`app.js` 用到的每个 `#id` 在 `index.html` 里存在、顶栏就是三个屏且每屏有对应 `<section>`、
iframe 的 `src` 文件真实存在、`data-go` 指向存在的屏、用到的 `/api/*` 在 `server.py` 里真有路由、
**35 个能力控件一个都没丢**（构建/烧写/列串口/固件列表/板子状态/确认升级成功/预览/编辑器/
写两块板/读角色/退出）、
**三步流程与去术语**（两张板卡 + 一个「开始升级」按钮；「高级」以外不许出现那批术语），
以及 2026-10-16 新加的三段：

- **表盘屏只有一个编辑器**：外壳里出现的编辑器地址只许有一个
  （`/tools/theme-editor/index.html`），图片入口落到它的 `#images`，
  而 `image-editor.html` 仍然只是**无脚本**的跳转薄壳（老链接还能用），外壳不再引用它；
- **编辑器只在客户端里走本机能力**：用现成的 `/api/ports` + `/api/upload` + `/api/flash`，
  `kind` 固定 `assets`，**请求体里没有偏移这个字段**，那块面板默认隐藏；
- **端口标角色 + 一次写两块板**（21 条）：下拉用的是服务端给的 `p.label`（带角色）；
  外壳里**不许**出现"哪个 COM 号 = 哪个角色"的硬编码、也不许自己造角色；
  两块那条路先亮出"将要写这两块"，只写 `is_project_board` 的板，逐块 `await`、
  **逐块报结果**，有失败时状态栏说的是"没写成"（不假装成功）；
  `server.py` 里 `/api/flash` 仍然**只有一个入口**、也没有引入任何串口库；
- **刷之前不用保存、不产生下载**（15 条）：两颗写入按钮都走 `buildAssetsInMemory()`
  （现场用编辑器当前状态打容器）；外壳里没有 `createObjectURL`、没有 `<a download>`、

- **「点了没反应」那一课**（14 条）：表盘屏上就有那两颗写入按钮（与工具屏同一份实现
  `doWrite`）；点下去按钮自己变「正在写…」；编辑器页缺函数 ⇒ 喊「版本过旧」+ 怎么更新；
  外壳与编辑器**同一个来源**（`pages_source()` 一处决定）；**所有静态响应 no-cache**；

## 已知注意

- **编辑器的旧保存看不到**：编辑器用 `localStorage`，而旧入口是 `file://`（另一个源）。
  第一次从新入口打开时，配色/图片页里的"上次保存"会是空的 —— 旧入口仍然可用，
  需要旧数据就从旧入口导出一次再导进来。
- **无线刷写要求板子在 OTA 模式**：那是板子自己起的热点，你连上它之后本应用才能
  `POST http://192.168.4.1/update`；板子自带的上传页（手机浏览器开 `192.168.4.1`）
  仍然是备份路径。
- **构建/烧写会占用串口**：别同时开着别的串口监视器。
- **角色认不出来是正常的，不是坏了**：认角色要证据（USB 的 `SER=` ↔ 板子自己起的 AP 名 /
  它自报的 `role=`）。电脑没连板子的 WiFi、板子是哑的、或者别人家的板子换了 MAC 时，
  下拉就写「角色未知」——**那是如实显示，不是猜错**。三条能改观的做法：
  ① 电脑 WiFi 连一次那块板子的 `206dash-…`，再点「读一下角色」；② 走一次无线升级
  （升级流程本来就会读 `/status`，顺手就把角色学了）；③ 手动编辑
  `C:\206dash-scratch\app-board-roles.json`（里面每一条都记着**证据来源**；删掉它 = 忘掉重认）。
  缓存来的角色会带「未确认」标记 —— 未确认就是未确认。
- **「写进两块板」只写认出来的本项目的板**：主板板载串口（`ACPI\PNP0501` 那种）不在里面；
  一块都没认出来时它会让你先「刷新串口」，而不是硬写一个不知道是什么的口。
- **「写进这块板 / 写进两块板」刷的是「表盘」屏那个编辑器框里的当前状态**：如果你是
  **另开窗口**改的（「在新窗口打开」），外壳看不到那个窗口的状态 —— 在表盘屏那个框里
  也打开/刷新一次就行（或者先「保存安装包」存一份，再从折叠区那条路刷）。
  另外：编辑器里的图片是**内存里**的，刷新页面就没了 ⇒ "刷之前要保存"不是必须的，
  但**想把这些图留着**（比如以后还要改）就得先保存一份 —— 那正是「保存安装包」的用处。
