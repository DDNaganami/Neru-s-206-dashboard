206Dash 工具入口

这是 206 仪表盘的主题 / 素材工具：把配色和图片做成两个文件， 用 esptool 刷进仪表的两个分区就生效 —— 换配色、换图都不用重新编译固件。

下面四页都是双击打开就能用的静态网页：不需要联网、不需要装东西、不需要起本地服务。 本页只是入口，四页本身一个字节都没被合并。

四页顶部都有一条同一条导航条：最左边那个「← 返回导航页」就是回到这里， 右边四个按钮可以直接在这四页之间互相跳 —— 不需要再用浏览器的后退键。

四个页面

① 配色（主题编辑器）

底色 + 四条弧 + 四处读数文字颜色

干什么：调背景色、两条外弧（转速 / 车速）与两条内弧（水温 / 进气温度）的 点亮色 / 轨道色 / 角度 / 半径 / 线宽，以及屏上四处文字（大数字、单位、水温、进气温度）的颜色、 字号档位与位置；还能播开机动画。

什么时候用：想改颜色、想调弧的开口方向或粗细、觉得读数位置不合适时。 换了一张浅色底图之后"屏上的字看不见"也是一个典型场景（那一页和图片页都能改字的颜色）。

产出：theme.json ⇒ 刷 theme 分区。

打开配色页 →
tools/theme-editor/index.html

② 图片素材（图片编辑器）

加图片 + 选用途 + 导出 image.bin

干什么：把 PNG / JPG / WebP 拖进去，给每张图选用途 （表盘背景，或左屏 / 右屏各 5 档表情之一），页面按目标板做规格检查与自动转换 （尺寸、透明通道、圆形可视区），并给出两屏合成预览与占空间条。

什么时候用：要放自己的背景图或表情图时 —— 这是唯一的上传入口 （预览那两页没有上传）。同一页也能改配色并导出 theme.json。

产出：image.bin ⇒ 刷 image 分区。

打开图片页 →
tools/theme-editor/image-editor.html

③ 看帧（宿主机预览）

看 pcpreview 落盘的真实渲染帧

干什么：循环播放 preview/frames/ 里的 l_*.bmp / r_*.bmp —— 那是 LVGL 在宿主机上用与真屏同一套 UI 代码渲染出来的， 并且页面上写着怎么把它跑出来。

什么时候用：刷板之前先看一眼"这一套配色 / 图片到底长什么样"。 跑一次 pcpreview 会落 150 对帧（30 秒、5fps）。

打开看帧页 →
preview/preview.html

④ 圆屏参照（双 2.8C）

圆边虚线 + px ↔ mm + 能验 / 验不了

干什么：同一个帧播放，但页面上多一圈青色虚线 = 真机能看见的边界 （虚线圈以外在真机上看不见），另给出画布 px 与面板 mm 的换算表、键盘与控制文件的 注入清单、以及"这一页能验什么、验不了什么"。

什么时候用：做素材时判断"内容有没有伸到圆外"、或者要确认 "某件事根本不该指望在预览里看出来"时。

打开 2.8C 参照页 →
preview/preview-28c.html

工作流顺序（按这个顺序做，不会白做）

  1. 先配颜色 —— 打开① 配色页， 调底色、四条弧、四处读数文字，满意后点右上角「导出主题文件」得到 theme.json。
    先定色再配图：底色和弧色的深浅会决定你要选什么颜色的表情图。
  2. 再做图片 —— 打开② 图片页， 拖图进去、逐张选「用途」、看规格检查有没有报警，然后点「导出 image.bin」。
    配色页导出的 theme.json 可以在这一页「读入」，预览就与配色一致了（两页也共用同一份本机配色）。
  3. 刷进设备 —— 用 esptool 把两个文件写到各自的分区，然后复位。
    命令见下面「刷写命令」，偏移与大小都从分区表现场核对过。
  4. 再跑一次 pcpreview 看效果 —— 跑 python -m platformio run -e pcpreview -t exec（跑够了几秒按 Ctrl+C）， 然后打开③ 看帧页或 ④ 圆屏参照页。
    帧里的画面与真屏是同一套 UI 代码渲染的，所以配色与素材的改动在这一步就能看到。
★ 两个分区是两次刷写：配色在 theme 分区、图片在 image 分区。 只改了颜色就只刷 theme，只换了图就只刷 image；两个都改了就要各刷一次 （刷一个不会带上另一个 —— 这一点最容易漏，漏了的症状是"改了没生效"）。

刷写命令（把端口改成你自己的）

目标板 = 双 2.8C 圆屏（最终板）：两块 480×480 圆屏，各由一块 ESP32-S3 N16R8（16MB flash）驱动，分区表是 partitions-s3.csv。 两块屏刷同一份 image.bin 与 theme.json。

分区偏移大小刷什么
theme0x2100000x4000（16 KB）theme.json
image0x2540000x800000（8 MB）image.bin

出处：partitions-s3.csv 的 theme 行与 image 行 （偏移与经典板的 partitions.csv 刻意相同）。设备端 theme 缓冲只有 4096 字节（lib/themetool/theme_store.h），所以 theme.json 别超过 4 KB —— 配色页导出时会自己检查并提示。 

# ① 配色 ⇒ theme 分区（COM6 是这台机器上的口，改成你自己的）
python -m esptool --chip esp32s3 --port COM6 --baud 921600 write_flash 0x210000 theme.json

# ② 图片 ⇒ image 分区（8 MB）
python -m esptool --chip esp32s3 --port COM6 --baud 921600 write_flash 0x254000 image.bin

★ 端口改成你自己的：COM6 只是这台机器上的值，在设备管理器里看一眼再填。 2.8C 的刷写与监视走板载 UART（那个 Type-C 口，板载 CH343P）。 

# ③ esptool 没装在系统 python 里时（报 No module named 'esptool' / 'intelhex'）：
#    先把三个路径挂上 PYTHONPATH。这台机器上的写法（路径照抄自 tools/theme-editor/README.md）：
$env:PYTHONPATH='C:\Users\Public\206dash\.pio-core\packages\tool-esptoolpy;C:\Users\Public\206dash\stubs;C:\Users\张九思\206Dash\.pio-pylibs'

成功以 esptool 最后那行 Hash of data verified. 为准。 ★ 写错偏移 esptool 照样会打这句话 —— 症状是"屏上什么都没变"； 而且写偏了有可能会压掉旁边那个只有 16 KB 的 theme 区，所以偏移别凭记忆填。

预览看不到什么（别被预览误导）

③④ 两页放的是宿主机落下来的帧，它们能证明的是"该画的东西画出来了、位置 / 配色 / 亮灭对不对、 有没有伸到圆外"。而下面这几类在预览里结构上不可能出现 —— 不是"还没做"，是"预览这条路根本没有那一段"： 撕裂、图像残留、横纹 / 抖动、真实帧率与时序。

原因与完整清单（含面板初始化、字体墨迹、圆屏物理边框内缩）见 docs/PREVIEW.md 的 第 4 节「★ 预览看不到什么」 —— 那一节是这条口径的唯一出处，判据与打点在 docs/RGB-PANEL-2.8C.md。 所以"预览看着没问题"≠"真机没问题"。

已知限制（都是预期，不是故障）

  • ③④ 两页只显示落盘的帧，没有上传入口。 要传图片素材请用② 图片页 （那里才有"加图片 / 选用途 / 导出 image.bin"）。 另外这两页显示的是 preview/frames/ 里已经存在的帧： 目录是空的时候页面上就是两块黑画布 —— 先跑一次 pcpreview 再开。
  • 底下那六格指示灯是程序化画的占位图形，不需要任何素材。 它们是代码里的简单几何（方框 + 图形），不占 image 分区、也不用你准备图片； 它们的颜色在① 配色页里改。
  • 台上不接 VAN 时：六格全灭 + 表盘右缘出现 SIM 角标 = 预期，不是故障。 没有真实车辆数据时，车速 / 转速 / 水温 / 进气四格的来源恒为"模拟"， 于是"数据不可信"提示按判据（正确地）亮起来，六格灯全部熄灭。 接上 VAN、有真实帧之后角标自己就消失 —— 不需要改任何设置。
