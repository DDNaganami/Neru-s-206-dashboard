# 台面观察日志（BENCH-LOG）

**为什么有这份文件**：屏幕上的现象（横纹 / 偏移 / 黑块 / 黑屏）**只有车主看得见**，
而串口日志只能证明"芯片/驱动侧有没有留下签名"。两边分开记，事后才能对齐 ——
以前这些现象只存在聊天里，回查不了。

**记法**（一行一条；现象写眼睛看到的原话，证据指向具体日志文件）：

```
日期 时间 | 板 | 现象 | 当时 uptime / 有无复位 | 证据文件 | 处置
```

★ **4 小时 0 复位怎么读**（别读成"WDT 已解决"）：10-11 那夜的量级是 **10.2 h / 5 次**（≈2 h 一次）

★ 采集本身不会打断板子：这次日志起点**没有 `boot:` 行** ⇒ 打开串口没有复位它 ✓（与 esptool 的复位/哑掉是两码事）。

★ 新签名：**WDT**（这一类里首次出现）⇒ 指向「跑一段时间后挂住」，而不是面板/供电瞬态。
★ 头号嫌疑（**可能是我引入的**）：从板是唯一带 BLE 的板，而我把它的 BLE「发现服务」
  从主循环搬到了**独立任务**；若那条路径能挂住就会表现成 WDT，且**只影响从板** ✓。
  从板 `app0` 里仍留着**改动前**的固件 ⇒ 回滚 A/B 是现成可用的 ✓。
★ 教训（写给以后的自己）：凡会改变板子**可见状态**的实验（进 OTA 模式=黑屏、复位、重刷），
  做完必须立刻说明"它现在是什么状态、多久恢复"——这次我让主板黑了很久才说 ✗。
