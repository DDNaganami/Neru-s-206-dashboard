**为什么有这份文件**：屏幕上的现象（横纹 / 偏移 / 黑块 / 黑屏）**只有车主看得见**，
而串口日志只能证明"芯片/驱动侧有没有留下签名"。两边分开记，事后才能对齐 ——
以前这些现象只存在聊天里，回查不了。

**记法**（一行一条；现象写眼睛看到的原话，证据指向具体日志文件）：

```
日期 时间 | 板 | 现象 | 当时 uptime / 有无复位 | 证据文件 | 处置
```

★★ **今天最值得追的一条：② 自愈了**。车主看到偏移后**没做任何操作**，它自己还原了 ——
这与 `RGB-PANEL-2.8C.md` §20 那条"**只有按复位键才有效**"的旧结论**相矛盾**。
能分辨"是重启才好的"还是"守护自愈"的**只有板子自己那两行**：

```

link: B uptime=...ms                          ← 每 5 秒那行
```

⇒ **下次能开串口的第一件事就是把这两行抄下来**：uptime 只有几十分钟 ⇒ **是重启才好的**；
uptime 几小时以上 ⇒ **是自愈**，那 §20/§4 的分类要改写。

### 2026-10-15 结案（10:34 抓到横幅，`retry-com9c.log`）

**串口是被"驱动层残留句柄"卡住的**（连 COM1 都 `Access denied`、且没有任何进程占着）：
断电拔插一次原生 USB（重新枚举）就好了 ✓；等待期间用 `probe-retry.ps1` 自动重试采集，
才没错过开机横幅。

横幅原文（两行，判据）：

```
rst:0x15 (USB_UART_CHIP_RESET),boot:0xb (SPI_FAST_FLASH_BOOT)      ← ROM 层：这次复位来自 USB 侧（我们开串口/拔插）
boot: reason=UNKNOWN n=33 (raw=11) up=242ms | prev=POWERON (raw=1) prev_up=30min | hb=292 | role=MASTER
```

★ **结论：早上的"偏移自愈"最可能就是一次上电复位（POWERON）** —— 它之前那一轮只跑了
**约 30 分钟**，时间点与"笔记本恢复时 USB 反复上下电"吻合（≈10:03）。上电复位会重新走
面板初始化 ⇒ 偏移自然没了。⇒ **`RGB-PANEL-2.8C.md` §20 的"只有复位键才有效"继续成立**，
不需要改写。
★ 口径（诚实起见）：横幅**能证明早上有 POWERON 复位**，但**不能 100% 证明**那个偏移就是被它清掉的
（当时没有日志）。以后再看到"自己好了"，先查 `n=`/`prev=`/`prev_up=` 三个数再下结论。
