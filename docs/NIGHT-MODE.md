# 夜间模式（设计单）—— 背光自适应 / 主题两套 / 底图夜间版

> 状态：**已开工**（2026-10-17 车主定方向："写吧，开工"）。
> 本文件是**设计单**（为什么、按什么顺序、判据是什么）；落地记录进 `ACCEPTANCE.md`。

## 0. 一句话结论

**机能完全够，而且不花 RAM。** 三件事（背光 / 配色 / 底图）都能在现有固件上做，
真正要小心的是**两条纪律**：① 切换只在"白天↔夜间"翻转时**写一次**；
② 夜晚别用"整屏半透明覆盖件"来压暗（那块地踩过，见 §5）。

## 1. 触发源：用车灯，不用时钟

| 候选 | 能不能用 | 说明 |
|---|---|---|
| **VAN 灯位**（`0x4FC`） | ★ **采用** | `VehicleState` 里**已经解好、且已过保持窗口**：`low_beam`（bit6 近光）、`position_lamp`（bit7 仪表盘灯）。零新增硬件、零对时。 |
| 板上 RTC（`PCF85063`） | ✗ 现在不行 | 硬件在板上，但**没有驱动**、也没有对时来源（`ARCHITECTURE` 里那条待确认）。要做"到点自动"得先加驱动 + 电池 + 对时，是另一条线。 |
| OBD / 手机时间 | ✗ | 车上不连手机；K 线 OBD 没有时间 PID。 |

**判定口径**（每块板各算各的，不跨板同步）：

- 进夜间：`low_beam || position_lamp` 连续成立 **≥ 3 s**（灯杆动作时 VAN 是 4.7 帧/秒，别用瞬时值）
- 回白天：两者都不成立 **≥ 10 s**（隧道/会车闪远光不该来回跳）
- **数据不可信**（`DataTrust != ok`）或**数据源不是 VAN** 时 → **保持当前态不动**（回白天会让夜间突然刺眼；
  保持不动最多是"该暗的没暗"）。★ 与告警层"宁可少报"同一口径。
- 熄火/重启后按"白天"起步，等灯信号再进夜间（不做 NVS 记忆：进车时灯是关的，记忆反而会错一帧）。

## 2. 增量 1：背光自适应（先做这个，性价比最高）

**为什么先做它**：夜里刺眼的主因是**亮度**，不是配色。而且它只动一处 PWM，不改任何格式。

- 白天基准 **75%**（2026-10-17 车主定；原来照抄例程的 50%，见 `src/dash_display_rgb.cpp` 的 `RGB_BL_PCT`）。
- 夜间目标 **30%**（待车主在车上定档；先按 30% 起步，白天/夜间两个数都是**常量**，改一行即可调）。
- 接口（新增，只存在于设备端）：

  ```
  void dash_display_set_backlight_pct(uint8_t pct);   // 0..100，内部折算 10 位占空比
  ```

  ★ 必须**同时更新面板守护的影子值**（`PanelGuard::setBacklightDuty()`）—— 守护每 2 s 回读一次占空比，
  影子不同步就会被它当成"背光被改了"重写回去（`src/dash_display_rgb.cpp` 的 `pan_guard_write_duty`）。
  pcpreview / SPI 档给**空实现**（宿主机没有 LEDC）。
- 只在**目标档位变化**时调用一次，并打一行日志（纯 ASCII，便于判读）：

  ```
  bl: night=1 pct=30 (lamp=low_beam)
  ```

- **判据**：
  1. 上板读日志：`rgb: 板=… @75%`（白天基准）→ 灯信号注入后出现 `bl: night=1 …`；
  2. `panelguard` 之后**不再重写**背光（没有 `panelguard: backlight rd=… -> rewritten` 那一行）；
  3. 台面可验：用车灯回放/注入（`van_replay` 或 `preview/inject.txt` 的 `L`/`P`）触发，看两行日志。

## 3. 增量 2：主题两套（格式修订 **R5**）

**做法**：同一个 16 KB `theme` 分区里放**两套**（索引头 + day JSON + night JSON），
`Theme` 结构体在 RAM 里开**两个槽**（≈0.8 KB），切换 = **样式重放**，不重建对象。

- **不重建 UI 的理由**：重建要销毁/重建两屏几十个 LVGL 对象、还可能牵出开机动画；
  而所有颜色/线宽/透明度都写在**已存在**的对象上，重放一遍即可（几毫秒 + 一次整屏重绘 = 23 ms @43 Hz）。
- **不需要新分区**：现在一份主题才 2,975 B，16 KB 放 5 份都够。
- **兼容**：分区里只有一套时（老文件/老导出）⇒ `night` 槽 = `day` 槽的副本，等于"永远白天"，
  老主题照旧能跑。**不加版本号字段**（本仓库靠"按键名寻址 + 缺键继承默认"，见 `lib/themetool/ui_theme.h`）。
- **★ 纪律**：`theme_apply_style()` 只在**翻转的那一帧**调一次；它内部只写样式、**不比较值**，
  所以**不许**放进渲染循环（2026-10-15 那次"跟着刷新移动的横纹"就是这么来的：
  逐帧写样式 ⇒ 每帧 5 次重绘 ⇒ `inv=` 冲到 856,980 px²/s）。
- **判据**：落帧跑两套主题各 150 对，`inv=` 在切换那一帧只跳一次、之后回常态；
  像素判据复用 `check-preview-frame.js` 的口径。

## 4. 增量 3：底图夜间版（新角色 **23**）

- **格式不用改**：`image_blob.h` 的编号表已经写明"**下一个新角色用 23**" ⇒ 加一个
  `BackgroundNight = 23`（底图是**两屏共用一张**，所以一张管两块屏）。
  ★ 保留编号（2/5/7/9/10/11/14/15/16/19/20）**一律不复用**，理由见那个头文件。
- **容量（实测账）**：`image` 分区 **8 MB** @`0x254000`；一张 480×480 **RGB565 底图 = 450 KB**
  （cf=0x12，实测）⇒ **约 17 张满幅**。现在里面装的是 1.84 MB（1 底图 + 8 张 240×240 表情，每张 168.75 KB）。
  ⇒ 加一张夜间底图只占分区 **5.6%**；连"夜间全套表情"一起做也才 46%。
- **RAM 成本 = 0**：图片是 `esp_partition_mmap` **零拷贝**用的（`src/image_load.cpp` 文件头写明
  `LV_IMAGE_SRC_VARIABLE` 路径**不会把像素复制到 RAM**）。
- **切换成本**：一次 `lv_image_set_src(bg, &night_dsc)` + **一次整屏重绘**。
- **判据**：切换后读 `rgb: vsync=… blit_max=… phase_max=… copy_max=…`，确认没有把 bounce 缓冲压穿
  （压穿的形态就是横纹/撕裂回归）；两张底图的落帧都要过 `check-preview-frame.js`。
- **闪写流不变**：夜间底图跟着 `assets.bin` 一起走"写进板子"，偏移仍然只有 `0x254000` 那一个白名单值。

## 5. 明确**不做**的两件事（都是踩过的坑）

1. ★ **整屏半透明黑覆盖件压暗**：LVGL 见到整屏大小 + `opa<255` 的对象会给整屏渲染开**离屏层**，
   而层缓冲从显示缓冲里切、**装不下整屏** ⇒ 下半屏内容回绕到顶部（记在 `src/dash_ui.cpp` 的注释里）。
   ⇒ 要暗就**降背光**或**换暗底图**，别用透明覆盖件。
2. **给主题格式加版本号字段**：现在是"按键名寻址 + 缺键继承默认 + 不认识的键跳过"，
   加版本号只会多一个会说谎的地方（`ui_theme.h` 里 R2/R3/R4 的注记就是这个口径）。

## 8. ★★ 素材与主题的存放契约（**R5**，固件与编辑器必须逐字一致）

### 8.1 `theme.json`（16 KB 分区 @ `0x210000`）

```json
{
  "theme": { …白天那一套（形状与今天完全相同，一个字都没改）… },
  "night": { …夜间那一套；**形状同上**，缺的键 ⇒ 继承 `theme` 里同名键… }
}
```

- **兼容**：老文件/老导出**只有 `theme`** ⇒ 夜间槽 = 白天槽的副本 ⇒ 永远白天，一个字节都不会画错。
  （本仓库没有主题版本号字段，兼容靠"按键名寻址 + 缺键继承默认 + 不认识的键跳过"。）
- 容量：现在一份 2,975 B，两份约 **6 KB** < 16 KB ✓。
- `Theme` 结构体 ~0.4 KB ⇒ RAM 里放**两个槽** 0.8 KB（可以忽略）。
- **指纹必变**：`themeJsonSha256` / `assetsBinSha256`（主题在容器里）会变 ⇒ 按规矩重生成
  `tools/theme-editor/.golden-hashes.json`，并在 `lib/themetool/ui_theme.h` 记一条 **修订 R5**。

### 8.2 `image` 段（8 MB 分区 @ `0x254000`）

- 新增角色 **23 = `BackgroundNight`**（`image_blob.h` 注释里已预留："下一个新角色用 23"）。
- 要求与现有底图完全相同：**480×480 / RGB565（cf=0x12）/ alpha 任意**（一张 **450 KB**）。
  两屏**共用**一张（与角色 1 一样），所以夜间只有一条素材。
- 三处编号表必须同步（native 用例 `test_role_ids` 会逐条对账）：
  `lib/themetool/image_blob.h` 的 `ImageRole` ⇄ `tools/theme-editor/image-blob-build.js` 的 `ROLE`
  ⇄ `tools/theme-editor/asset-spec.js` 的 `ROLES`。
- **保留编号一律不复用**（2/5/7/9/10/11/14/15/16/19/20），理由见 `image_blob.h` 那张表。
- **指纹必变**：`imageBinSha256` / `assetsBinSha256`。

### 8.3 刷写流不变

夜间素材跟白天素材**同一个 `assets.bin`**、同一个偏移白名单（`theme` `0x210000` / `image` `0x254000`），
"写进板子"一键带下去，不新增任何按钮。

## 7. 与装车的关系

- 三条增量都**不依赖车上有 VAN**：台面用灯光回放/注入就能验触发逻辑；真值判据在车上。
- 装车之后才定的两个数：**夜间亮度档**（30% 起步，车上看着调）、**夜间配色基调**
  （深底冷灰字 vs 深底暖色 —— 车主未定）。

### 2.1 落地记录（2026-10-20，增量① 已上板）

- 判据抽成纯函数 `lib/dashcore/night_mode.h`（3 s 进 / 10 s 出 / 抖动重计时 / 数据不可信时保持），
  native 新增 **6 条**用例（总数 387 → **393 例 / 2 跳过 / 391 通过**）。
- 背光接口 `dash_display_set_backlight_pct()`：RGB 档真实现（**同步面板守护影子**），
  pcpreview / SPI 档空实现；三个文件用 `#if` 互斥，保证**只有一个定义**（第一版漏了，链接期 duplicate symbol）。
- **台面实测（从板 COM8）**：用 USB 回放行喂 `VAN 4FC …C0`（bit6 近光 + bit7 仪表盘灯）⇒
  `SRC-VAN … low=van pos=van` ⇒ **`bl: night=1 pct=30 (lamp=low_beam)`**；灯灭 12 s 后
  **`bl: night=0 pct=75 (lamp=off)`**；全程**没有** `panelguard: backlight … rewritten`
  ⇒ 影子同步这条成立。
- ⏳ **主板（COM9）在台面上没翻到夜间**：灯位照样解出来了（`low=van pos=van`）、
  但 `bl:` 一行没出现 ⇒ 最可能是 `trust` 判据在"无 VAN 总线、速度/转速都是 Sim"的空板上
  不是 `kNone`（这是**设计如此**：数据不可信时不翻转）。车上 VLAN 真值到位后会成立，
  **待车测确认**。下一批会给这行加一个"灯亮了但数据不可信 ⇒ 为什么不翻转"的限速诊断日志。
